## Acceptance and delivery states

### Source candidate

- Reviewed integration includes a manifest of installed source preservation and
  every intentional difference. No generic replacement of a deployed overlay.
- Context tests exercise ordinary memory/mail tool loops, large results,
  original and translated K3 shapes, multibyte text and genuine overflows.
  Calls that cannot fit refuse with a clear reason; ordinary fitting requests
  are not refused solely by the monetary byte upper bound.
- Monetary, read-only and sensitive runtime regression checks remain passing.
- The actual profile-resolution report distinguishes preserved overrides from
  table choices, downloaded/cache/build behavior and role pauses.
- Reconciled documentation, reviewed milestones and a separate final review
  describe exactly which acceptance has and has not run.

### Deployment-ready candidate

- The retained exact candidate passes authenticated ordinary `cs ask` queries
  through its actual selected transport and compares material claims with the
  same original sources on both affected profiles. A precise refusal is a
  diagnostic success, not a substitute for successful ordinary reads.
- Applicable real two-clone operational acceptance proves preservation of the
  send/draft/assignment boundaries on the integrated runtime. Historical R9
  evidence is retained and is not reused as new-candidate acceptance.
- Required model-table CI, direct/credits paid legs, server protocol and recovery
  evidence are current for the intended rollout; approved deferrals are explicit
  and do not waive this incident's ordinary-read and factual-quality criteria.
- Runtime identities, source/table hashes, installation scope and rollback are
  concrete. Any migration has a reviewed rehearsal before production use.

Deliver a source candidate when that is all evidence supports, with remaining
deployment gates individually owned and visible. Mark deployment-ready only
after the second set passes. No deployment or public release follows implicitly.
