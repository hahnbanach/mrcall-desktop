# Model selection end to end: milestone 10's AC 10, 2026-10-12

`docs/briefs/2026-10-01-model-selection-by-requirements.md` (hb). It covers:

## Verdict

- **Picks.** All 52 free cells and the 4 paid cells resolved all 16 roles as
  the oracle expected: 896 role resolutions, 0 mismatches. The extra checks
  also passed in every cell (listed below).
- **Explicit models.** No profile with an explicit model paused.
- **Credits.** Credits always ran the best served model.
- **Paid legs.** Three paid calls answered on OpenRouter, for USD 0.000052
  in total.
- **Pending.** The Anthropic direct legs need a valid Anthropic key (the key
  supplied was refused with HTTP 401). The credits paid leg needs the CTO's

No engine defect was found, and no engine code was changed.

Each cell is a real engine process:

1. It writes the profile's `.env` and activates the profile with
   `profiles.activate_profile`. This loads the last good copy and starts the
   background download.
2. It runs one download round itself (`distribution.refresh`) and runs
   `init_db`.
3. It resolves every role through `routed_model`, as call sites do, and
   reads `policy_snapshot()` (the Settings card).
4. It checks that every pick is priced (`prices.price`) and has request
   metadata (`catalogue.metadata`) on its transport.

The expected picks come from an oracle (`expect` in `m10_e2e.py`). The
oracle reads the tables as plain JSON and applies the documented rule
without the engine's resolver:

- OpenRouter: the first `ranking` id;
- Anthropic: the first `anthropic_ranking` direct id, or a pause when that
  ranking is empty;
- credits: the first ranked entry the server serves. That is its direct id
  when the server lists the direct id as Anthropic's, else its catalogue id
  when the server lists that as OpenRouter's, else a pause;
- custom: the explicit model, for every role.

The harness's comparison was itself checked against doctored results: a
changed pick, a missing pause, a wrong source, an accepted unpriced table, a
refused call that reserved something, and a custom profile that paused. Each
one failed the check.

### The scenarios

1. **Table downloaded (`downloaded`).** Each cell ran the engine's
   production fetcher against the real URL. The harness downloaded the same
   two files separately, as the oracle. In every cell the profile's cached
   `model-table/table.json` and `snapshot.json` are those bytes, and the
   versions in force are `f1847561…` and `571b55d2…`. The sources read
   `downloaded`.
2. **Download blocked (`blocked`).** These are fresh profiles, and every
   proxy variable points at `127.0.0.1:9`, where nothing listens. That
   variable is an environment seam the engine's HTTP client honours; no code
   was patched. Both downloads failed and were logged ("download failed:
   ConnectError: [Errno 111] Connection refused"). The build copies were in
   force (sources `build`, `304ab3b7…` / `b3196ae2…`), and the picks equal
   the build table's.
   - **`blocked-cached`.** The same block on the `downloaded` profiles, which
     hold a last good copy. The cached published copy stays in force
     (sources `cached`, `f1847561…`), as the distribution specifies: the
     last good copy first, then the build copy. This check goes beyond the
     scenario the brief names.
3. **Simulated successor (`successor`).** A fake data branch, served
   through the distribution's fetcher seam (`refresh(fetch=)`), published
   the downloaded copies changed in two ways:
   - The snapshot adds `anthropic/claude-sonnet-6`, direct id
     `claude-sonnet-6`, an id unknown to the engine. It copies Sonnet 5.5's
     metadata, endpoints and price (USD 2 / 10, within both ceilings).
   - The table ranks Sonnet 6 wherever Sonnet 5.5 was ranked. This is the
     same construction as S6's `successor_is_the_pick`, applied to the live
     table.

   Egress stayed blocked so that the background download could not replace
   the fake branch's copy. Then the branch published a table that also
   ranks `anthropic/claude-sonnet-7` (no snapshot entry) first for CHAT
   under both presets.

**A priced pick works.** Sonnet 6 is priced on both transports from the
downloaded snapshot alone: `claude-sonnet-6` direct and

request metadata. The custom profile saved with `claude-sonnet-6` resolves

**What the snapshot cannot price is refused, never guessed.**

- **A table ranking an unpriced id.** In all four OpenRouter and Anthropic
  cells, the table that ranks `anthropic/claude-sonnet-7` first was refused
  by the gates. The log reads: "downloaded table refused: … CHAT / ranking:
  anthropic/claude-sonnet-7 is not in the snapshot". The table in force

    for this model.";
  - OpenRouter `anthropic/claude-sonnet-7`: "AI paused: OpenRouter model has
    no verified price ceiling.".

  Neither call left a reservation or a usage row. Both profiles carried a
  placeholder key, so even a call that had escaped admission would have been
  refused by the provider.

## Paid legs

The paid legs ran on the published table (`downloaded`), each in its own
scratch profile:

- each profile had `LLM_DAILY_BUDGET_USD=0.30`, so the engine's durable
  reservation ledger refuses past it;
- the harness journalled the engine's own reservation bound against the
  USD 2 cap before each call;
- the four profiles' budgets sum to USD 1.20, so the total could not reach
  USD 2;
- nothing was retried.

Each call went through `make_llm_client(routed_model(...))` and
`create_message_sync`. The prompt was "Reply with the single word: ready",
with `max_tokens` 48 (the request shape adds 1024 tokens of headroom where
the model may reason).

| Leg | Role | Picked model | Answered by | Bound (USD) | Settled (USD) | Tokens in / out | Answer |
|---|---|---|---|---|---|---|---|
| OpenRouter, economy | TASK_DETECTION | `mistralai/ministral-8b-2512` | same | 0.001023 | 0.000009 | 52 / 7 | "Understood. **Ready.**" |
| OpenRouter, balanced | NARRATION | `inception/mercury-2.5` | same | 0.000475 | 0.000039 | 68 / 236 | "ready" |
| Custom, explicit `z-ai/glm-5.3-flash` (OpenRouter key) | NARRATION | `z-ai/glm-5.3-flash` | same | 0.001696 | 0.000004 | 51 / 3 | "ready" |
| Anthropic key, economy | MEMORY_EXTRACT | `claude-sonnet-5` | — | 0.032580 | 0 | — | HTTP 401 `authentication_error` ("invalid x-api-key") |

- **Total settled:** USD 0.000052 (52 micro-USD) of the USD 2 cap. The
  bounds of all four calls totalled USD 0.035774.
- **OpenRouter legs.** Each answer named the requested model. Each
  reservation settled from OpenRouter's receipt into `llm_usage`, under call
  site `ac10.<role>`, leaving nothing reserved.
- **The 401.** It counts as a refusal before inference, so its hold was
  released as a zero-cost row, leaving nothing reserved. Per the
  instructions, the Anthropic leg was not retried. The Anthropic balanced leg
  (NARRATION, `claude-sonnet-4-5`) and the custom leg on the Anthropic key
  (NARRATION, `claude-sonnet-4-6`) were not attempted. The one custom paid
  call therefore ran on the OpenRouter key. Like the Anthropic custom
  profile, it ran NARRATION, a role that pauses under economy on the
  Anthropic key; it did not pause.

Keys came only from `OPENROUTER_API_KEY` and `MNEMONIC_ANTHROPIC_API_KEY`.
Each key was written only to its paid cell's scratch `.env`. After the runs:

- every `.env` under the scratch tree was deleted, and a scan found none
  left;
- no log, result file or profile database held a key or a fragment of one.

## Reproduce

From `engine/`, with `HOME` left as is (each cell gets its own scratch
`HOME`), run:

```bash
python scripts/m10_e2e.py --root <scratch>/free --out matrix.json        # free, no key
python scripts/m10_e2e.py --root <scratch>/paid --paid --out paid.json   # paid, keys from the environment
```

Exit 0 means no mismatch, no failed check, no crash, no key in a log and no
`.env` left.
