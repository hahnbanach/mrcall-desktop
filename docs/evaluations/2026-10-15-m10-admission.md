# M10 local context admission evidence

Scope: M2 of the approved [readiness plan](../execution-plans/2026-10-15-m10-memory-production-readiness.md).
This is local source evidence. It preserves the prior M10 measurements and
conditional approval; it does not replace provider or deployment acceptance.

## Current policy

OpenRouter input fit is decided by provider tokenization. Neither the monetary
one-token-per-byte bound nor the direct Anthropic corpus estimate is used as
an OpenRouter context estimate. This applies to original Messages requests and
the K3 translated Chat body. The direct Anthropic context decision is unchanged.
The common text/function feature validation is reused without its direct-only
pricing and context decisions.

Output remains finite: the existing 131072-token ceiling is narrowed by a
positive snapshot `context_length`, with an output reserve equal to or above
that context refused because a nonempty input needs room. K3 reasoning retains
its 8192-token combined output cap and adaptive/max controls. Schema 1 publishes
context length but no separate maximum-output capability. The finite fallback
is a local safety limit, not evidence that every provider accepts that output.
No tokenizer ratio is asserted for K3. Existing assistant prompt and per-result
limits remain in force.

Money remains conservatively reserved from bytes, complete output allowances
and protocol overhead. Messages reserves the larger of original and dispatched
bodies. K3 retains the larger of its original reservation and translated Chat
reservation. All input for Anthropic through OpenRouter still reserves the
one-hour cache-write maximum. Snapshot prices, margin, price ceilings,
quantization policy and K3's DigitalOcean pin remain unchanged.

Both local OpenRouter wire formats explicitly send
`plugins: [{"id": "context-compression", "enabled": false}]`.
[OpenRouter's message-transform documentation](https://openrouter.ai/docs/guides/features/message-transforms)
states that compression can remove or truncate messages and defaults on
endpoints with context at most 8192 tokens. The explicit control prevents relying
on that default. No compression request, local evidence truncation, model change,
inference retry or overflow retry is added. Historical K3 wire fixtures remain
intact; their checks declare this additional policy field and compare every
other field after the previously reviewed temperature and price differences.

The MrCall credits quote/request shape is unchanged. Its server independently
constructs the provider wire. Server-side compression disabling and matching
admission/cost behavior remain an external integration prerequisite; this local
change does not establish their enforcement. The lead's read-only server
orientation also found that the bounded billing contract retains OpenRouter/K3
byte-context admission. Equivalent server input-admission compatibility is
required alongside the compression control; promotion of the existing server
commit alone is not evidence that large credits questions will work.

## Semantic evidence

`tests/llm/test_provider_context_admission.py` exercises the actual guarded
client, temporary SQLite ledger and HTTP adapter with scripted responses:

- A short ordinary question followed by large memory/mail JSON results reaches
  Messages and K3 Chat once, with source dates, multibyte text, schemas and
  evidence intact. A monetary hold covering the full evidence and output is
  present during dispatch and settles on the receipt.
- Original K3 Messages and translated Chat pass local admission above both old
  byte thresholds; the same large request still triggers the unchanged direct
  Anthropic context gate. Escaped historical function arguments enlarge Chat
  and keep the larger monetary reservation.
- Replayed Messages reasoning, system blocks and schemas survive unchanged.
  Unknown options, multimodal/server-tool shapes and invalid output caps fail
  before dispatch. A changed snapshot context affects the next output check.
  Absent metadata retains the finite fallback, and unrelated direct models are
  unnecessary for OpenRouter admission.
- Scripted HTTP 400/413 overflow refusals release holds. HTTP 503, malformed
  HTTP 200 and timeouts retain them, even when an untrusted body claims a
  no-work status. Each admitted attempt dispatches once. Existing errors retain
  HTTP status without logging arbitrary upstream company payloads.
- An endpoint whose snapshot context is 8192 explicitly receives the disabled
  compression policy. Existing K3 wire and credit-quote pins cover the rest of
  the request shape.

## Limits and remaining gates

These scripted results establish local admission, payload preservation and
accounting behavior. They do not establish real provider input fit, real
upstream overflow behavior, factual company-answer quality, real credit-server
policy, paid credit settlement, authenticated ordinary reads or deployment
readiness. The lead owns combined integration, milestone review, documentation
closure and the external gates in the approved plan. Historical M10 evidence
and conditional approval remain valid only for the scope they originally prove.
